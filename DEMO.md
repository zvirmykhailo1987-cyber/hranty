# Grants portal — demo guide

Everything you see is synthetic (generated by `app/seed_demo.py`). Start the demo with
`docker compose up --build` and open <http://localhost:8070>.

## Accounts

Each person has an individual account. In demo mode the sign-in page lists these demo accounts
and fills the form with one click; in production it lists nothing.

| Login | Password | Role | Rights |
|---|---|---|---|
| `marko` | `marko-demo-2026` | Software & analytics | admin, data (registry edits, programme documents), archive, record submission |
| `bohdan` | `bohdan-demo-2026` | Investors & negotiations | **sign-off** of documents |
| `oksana` | `oksana-demo-2026` | Communities & companies | requests, matching, applications |
| `halyna` | `halyna-demo-2026` | Requests & correspondence | record submission and result |

Demo passwords exist only in demo mode. The ingest API is disabled in the demo (no token configured).

## 3-minute walkthrough

1. **Sign in as `oksana`.** *Today* lists deadlines within 14 days, new strong matches, tasks and
   the "what changed" feed written by the daily self-maintenance job.
2. **Client requests → "Biogas plant 1 MW for a dairy farm".** Ranked programmes, each with
   "why this score": six components with weights and a reason; unknown data is "no data".
3. **Take a match into work** → an application is created at stage *Idea*.
4. **Applications → the application.** The next-stage panel shows the gate; it refuses to move on
   until its condition holds and says why.
5. **Upload a document as `oksana`, then try to sign it off** — `oksana` has no sign-off right (403).
   Sign in as `bohdan`, upload a new version and try to sign off **your own** document — refused:
   the author can never approve their own document. Sign off a document uploaded by someone else — accepted.
6. **Submission** can only be recorded by a person with the right (`halyna` or `marko`), with a date.
7. **Grant registry** — filters by focus area and status; programme cards with documents and terms.

## Shared demo accounts

The demo accounts are shared by every visitor, so in demo mode nothing can take them away from
the next one: there is no password, login or role editing in the web interface at all, "Sign out
everywhere" is refused with a clear message (it would sign out every other visitor), and a run of
wrong passwords only locks that client (per IP and per IP + login, 15 minutes) — never the account
for everyone. The public demo resets every night at 04:00 CET; a banner says so on every screen.

## Reset

```bash
docker compose down -v && docker compose up --build
```
